# Проект № 06. Учет личных расходов

**Предметная область:** финансы  
**Тема:** разработка приложения для учета личного бюджета  
**Язык реализации:** JavaScript, HTML, CSS

## 1. Цель и задачи
Цель проекта — разработать простое приложение, которое помогает пользователю фиксировать личные доходы и расходы, видеть текущий баланс и анализировать направления затрат.

Задачи:
1. Изучить способы учета личного бюджета и определить необходимые категории.
2. Описать пользователей и основные сценарии работы.
3. Спроектировать модель данных.
4. Реализовать операции добавления и удаления, расчет баланса, поиск, фильтрацию и отчет.
5. Проверить корректность ввода и протестировать приложение на типовых сценариях.

## 2. Анализ предметной области
Личный бюджет представляет собой учет поступлений и трат за определенный период. Основные подходы к учету:
- **Ручной учет:** записи в тетради или таблице. Он прост, но требует самостоятельно считать суммы.
- **Электронная таблица:** удобна для формул и графиков, однако пользователь должен поддерживать структуру таблицы.
- **Специализированное приложение:** автоматизирует расчеты, категоризацию и отчеты. Оно удобнее для повседневного использования, но может требовать защиты персональных данных и резервного копирования.

В проекте выбран вариант небольшого браузерного приложения. Он не требует установки или серверной инфраструктуры, а данные сохраняются локально. Категории расходов: продукты, транспорт, жилье, здоровье, развлечения, покупки, образование, связь и другое. Категории доходов: зарплата, подработка, подарок, стипендия, инвестиции и другое. Набор категорий можно расширить.

## 3. Пользователи и сценарии
**Основной пользователь:** человек, который хочет контролировать собственные финансы без подключения к банковскому счету.

**Сценарий 1 — добавить расход:**
1. Пользователь открывает приложение.
2. Нажимает «Добавить операцию» и выбирает «Расход».
3. Вводит описание, сумму, категорию и дату.
4. Нажимает «Сохранить».
5. Приложение проверяет данные, сохраняет запись и пересчитывает сводку.

**Сценарий 2 — добавить доход:** пользователь выбирает «Доход», указывает источник поступления и сумму. Доход учитывается в общей сумме поступлений и балансе.

**Сценарий 3 — найти операцию:** пользователь вводит часть описания или категории в поиск либо выбирает фильтр «Доходы»/«Расходы».

**Сценарий 4 — изучить отчет:** пользователь смотрит общую сумму расходов и распределение по категориям в сумме и процентах.

**Сценарий 5 — удалить ошибочную запись:** пользователь нажимает × у операции и подтверждает удаление. Сводка и отчет пересчитываются.

## 4. Модель данных
Каждая операция представлена объектом JavaScript:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | строка | Уникальный идентификатор записи |
| `type` | строка | Тип: `income` или `expense` |
| `description` | строка | Краткое описание операции |
| `amount` | число | Сумма в тенге, положительное целое число |
| `category` | строка | Категория операции |
| `date` | строка | Дата в формате `ГГГГ-ММ-ДД` |

Коллекция операций хранится в массиве `transactions`. Данные сериализуются в JSON и записываются в браузерное хранилище `localStorage` под ключом `personal-expenses-v1`.

Баланс вычисляется по формуле:

**Баланс = сумма доходов − сумма расходов.**

Доля категории расходов:

**Доля (%) = расходы категории / все расходы × 100%.**

## 5. Функциональные возможности
В проекте реализовано более четырех функций:
1. Добавление дохода или расхода.
2. Автоматический расчет доходов, расходов и баланса.
3. Просмотр отчета по категориям расходов.
4. Поиск по описанию и категории.
5. Фильтрация по типу операции.
6. Удаление записи с подтверждением.
7. Сохранение и восстановление данных после перезапуска страницы.

## 6. Применение основных конструкций программирования
- **Циклы и перебор коллекций:** `filter`, `reduce`, `map`, `sort` используются для суммирования, сортировки и отображения массива операций.
- **Функции:** `renderSummary`, `renderTransactions`, `renderReport`, `validateForm`, `saveTransactions` разделяют обязанности и упрощают сопровождение.
- **Массивы и объекты:** массив операций хранит записи, объекты описывают операцию и набор категорий.
- **Обработка строк:** `trim`, `toLocaleLowerCase`, `split`, шаблонные строки используются при поиске, форматировании даты и подготовке текста.
- **Структурированные данные:** данные сериализуются через `JSON.stringify` и восстанавливаются через `JSON.parse`.
- **Обработка ошибок:** чтение хранилища защищено `try/catch`, ввод проверяется перед сохранением.

## 7. Проверка ввода
Приложение проверяет:
- описание не пустое и не длиннее 70 символов;
- сумма является целым числом от 1 до 1 000 000 000 тенге;
- категория входит в список допустимых для выбранного типа;
- дата соответствует ожидаемому формату и не находится в будущем;
- при отображении пользовательский текст экранируется, чтобы не интерпретировать его как HTML.

Некорректная запись не добавляется; пользователь видит сообщение об ошибке.

## 8. Подход к разработке и жизненный цикл
Выбран итеративный подход: приложение создается небольшими этапами, и после каждого этапа можно проверить работающий результат.

1. **Анализ требований:** определены пользователи, сценарии и обязательные функции.
2. **Проектирование:** разработаны структура страниц, категории и модель операции.
3. **Реализация:** создан интерфейс, логика расчетов и локальное хранение.
4. **Тестирование:** подготовлены позитивные и негативные сценарии.
5. **Внедрение:** приложение запускается в браузере без установки.
6. **Сопровождение:** можно добавлять категории, экспорт данных, месячные фильтры и резервное копирование.

Преимущество итеративного подхода — ранняя проверка интерфейса и возможность быстро исправлять ошибки. Ограничение текущей версии — отсутствие серверной синхронизации и авторизации. Перед реальным использованием финансовых данных стоит добавить экспорт/резервное копирование и усилить защиту данных.

## 9. Ограничения и развитие
Текущая версия предназначена для учебной демонстрации. Она не подключается к банку, не синхронизирует данные между устройствами и не формирует серверные отчеты. Возможные улучшения: выбор периода, экспорт CSV, лимиты бюджета, диаграммы, редактирование записей и резервное копирование.

## 10. Вывод
В ходе проекта разработано браузерное приложение для учета личных доходов и расходов. Оно использует массивы, функции, циклы и методы обработки строк, работает со структурированными JSON-данными, проверяет ввод и формирует сводную финансовую информацию. Реализованные функции соответствуют основной цели — сделать учет личного бюджета понятным и доступным.
